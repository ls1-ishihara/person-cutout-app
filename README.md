# 人物透過カメラ

Windows 11でPCカメラの映像を取り込み、人物だけをリアルタイム表示するアプリです。背景はウィンドウ内でも透明になり、映像と推論はPC上だけで処理します。映像の保存やネットワーク送信は行いません。

## 配布版のビルド

1. Windows 11にPython 3.10以降をインストールします。
2. PowerShellでこのフォルダーを開き、次を実行します。

   ```powershell
   .\build.ps1
   ```

3. 配布フォルダー `dist\PersonCutout\` をそのまま配布します。起動ファイルは `PersonCutout.exe` です。

初回ビルド時はPythonパッケージの取得にインターネット接続が必要です。人物検出モデルは同梱済みで、アプリの実行時にインターネット接続は必要ありません。

## ソースからの起動

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

アプリを起動すると自動で既定のWindowsカメラ（カメラ番号0）を開始し、ウィンドウを閉じるとカメラを解放します。ボタンはありません。Windowsのカメラプライバシー設定で、デスクトップアプリのカメラ使用を許可してください。

## テスト

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests
```

## ウィンドウの輪郭と操作

ウィンドウは常に最前面に表示され、ほかのウィンドウを選択しても背面に隠れません。

タスクバーで選択するなどしてアクティブになると、ウィンドウの外周に青い実線を表示します。非アクティブ時は輪郭線を表示しません。ウィンドウ内をドラッグすると移動、縁や角をドラッグするとサイズ変更ができます。終了は `Esc`、`Alt+F4`、またはタスクバーのアイコンからウィンドウを閉じます。

正常終了時に最後の位置とサイズをユーザーごとの設定に保存し、次回起動時に復元します。設定はWindowsレジストリの `HKEY_CURRENT_USER\Software\PersonCutout\PersonCutout` に保存されます。モニター構成が変わった場合は、Qtが画面内に収まるよう復元位置を調整します。

## ジョーク効果（F1〜F12）

ウィンドウがアクティブな間、次のキーで効果を切り替えられます。効果は重ねがけできます。

| キー | 効果 |
|---|---|
| `F1` | 人物が約3秒かけて50%まで透過（再度押すと元に戻る） |
| `F2` | ネガポジ反転のON/OFF |
| `F3` | モザイク 4px → 8px → 16px → 解除（カメラ画素単位） |
| `F4` | 人物領域に変化があった8×8ブロックを矩形表示。押すたびに 緑 → 水色 → マゼンタ → オレンジ → 白 → 位置グラデーション → 時間で回るレインボー → 解除 |
| `F5` | ポスタリゼーション（4階調）のON/OFF |
| `F6` | グレースケール → セピア → 解除 |
| `F7` | ドット絵化：細かい（6px）→ 粗い（12px）→ 解除。限定パレット、くっきり輪郭、暗い縁取り |
| `F8` | マトリックス風：人物を緑の文字セルで描き、全面に文字の雨が降る（ON/OFF） |
| `F9` | 残像（動くと尾を引く）のON/OFF |
| `F10` | RGBずらしのみ → グリッチ追加 → 解除 |
| `F11` | 走査線（CRT風）のON/OFF |
| `F12` | シルエット化：黒 → ネオン → 解除 |
| `Backspace` | すべての効果をデフォルトに戻す（F1 の透過は約3秒かけて元に戻る） |

## ちらつきの抑制

人物マスクの透過度に、画素ごとの変化量に応じた適応型の時間平滑化を行います。小さな揺れは履歴を重視してちらつきを抑え、大きく変わった部分は最新マスクを優先して、5フレーム均等平均で生じていた残像を軽減します。映像の色は最新フレームのままで、映像全体の時間平均は行いません。初回フレームはそのまま表示し、カメラの起動時や画像サイズの変更時に履歴を初期化します。

透過度（0〜255）が前回の平滑化結果から16以下しか変化しない場合、最新値20%・履歴80%で更新します。変化量が16を超えると最新値の割合を段階的に増やし、96以上では最新値をそのまま採用します。動きそのものを検出する方式ではないため、大きな検出ノイズがある場合はちらつきが戻ったり、小さな変化では輪郭の追従が遅れたりすることがあります。

## 処理構成と性能

カメラ取得は専用スレッドで続け、推論側は常に最新の未処理フレームだけを受け取ります。推論中に古いフレームが溜まらないため、処理が遅れても表示遅延が増えません。色変換は1回にまとめ、平滑化とマスク変換は配列を使い回して再確保を減らしています。

合成画像で計測した1フレームあたりの処理時間（640×480、同梱モデル、CPU）は次のとおりです。環境によって変わります。

| 処理 | 最適化前 | 最適化後 |
|---|---|---|
| マスク→透過度変換 | 約6.7 ms | 約1.5 ms |
| 透過度の時間平滑化 | 約5.9 ms | 約0.5 ms |
| `segment_frame` 全体 | 約23.6 ms | 約11.2 ms |

カメラが30fpsの場合は、処理時間がフレーム間隔（約33ms）より十分短いため、表示は約30fpsのままです。透過度は丸めの境界で最大1/255だけ最適化前と異なる場合があります。

## 検出モデルとライセンス

同梱の `models\selfie_segmenter.tflite` はGoogle MediaPipeのSelfie Segmenterモデルです。人物の背景分離を目的とする軽量モデルをCPUで実行します。モデルのSHA-256は `191ac9529ae506ee0beefa6b2c945a172dab9d07d1e802a290a4e4038226658b` です。

- モデル: [MediaPipe Selfie Segmenter](https://huggingface.co/litert-community/MediaPipe-ImageSegmenter-Selfie-Square)
- モデルとタスクのドキュメント: [MediaPipe Image Segmenter](https://developers.google.com/edge/mediapipe/solutions/vision/image_segmenter)
- ライセンス: Apache-2.0。ライセンス本文は `licenses\APACHE-2.0.txt` にあります。

人物が小さい、複数人が異なる距離にいる、暗いなどの条件では、切り抜きの精度が下がることがあります。
